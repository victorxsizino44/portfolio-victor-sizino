## Eligible future Agent R content

- Approved profile and HD-01 chronology.
- Only HD-02 metric/geography representations.
- Public channels from HD-03; telephone/WhatsApp are prohibited.
- HD-04 education/languages and only individually evidence-eligible certifications.
- HD-05 cases and claims with public status.
- CV data only when derived from the same canonical records.
- Other professional content only after explicit human approval.

Non-professional personal content is prohibited by default. An exception requires the exact information, purpose, exposure, validity period and whether Agent R™ may reveal it.

## Future knowledge release contract

Each release MUST include release ID, version, checksum, source baseline, publication date, owner, human approval and rollback reference. Make must consume an identifiable release rather than an untracked manual copy. Direct CMS consultation is not approved; a future option requires a governed adapter with filtering, versioning and failure handling.

Agent R™:

- MUST NOT create facts about Victor using general model knowledge, inference or plausibility;
- MAY use general knowledge only to organize/explain approved content;
- MUST distinguish approved, unverified and absent information;
- MUST say that information is insufficient when no approved fact exists;
- MUST exclude `Superseded`, `Deprecated`, `Blocked`, private and `Requires Human Confirmation` data from public answers;
- MUST use quantitative claims only when public under HD-02/05;
- MUST make responses traceable to the knowledge release when the architecture supports it.

Logs may record request ID, status, latency, release ID and safe error category. They MUST NOT copy full questions/answers, secrets, private URLs, prompts or credentials.

## Required sanitized Make verification

Before knowledge migration, inventory the scenario modules/flow, exact model/version, system prompt/instructions without secrets, sources, embedded content, Data Stores/files/sheets/databases, payload transformations, input/output contract, timeout/retries, error handling, logs/retention, owner, last change and evidence of the active source.

Webhook URLs, tokens, credentials, private IDs and other secrets remain redacted. Until this inspection is complete, all unknown scenario details remain `Requires Current Verification`; missing facts needing owner evidence remain `Requires Human Confirmation`.

## Reversal and boundaries

Future rollback selects the preceding approved knowledge release and records actor/time/result. The current Make scenario and Agent R JSON remain untouched in Phase 01. Agent B remains `Blocked`; no runtime, ingestion or autonomous capability is inferred from its prototype.
